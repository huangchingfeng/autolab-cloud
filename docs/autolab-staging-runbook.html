Staging Env Gate

先建立私密 .env.staging，填入真正的 staging service keys。可以用 bootstrap 腳本建立檔案並自動產生 JWT_SECRET；它不會覆蓋既有檔案，除非明確加 --force。

npm run staging:init-env -- \
  --write \
  --html=/Users/huangjingfeng/Desktop/專案/_reports/autolab-staging-env-bootstrap.html \
  --json=/Users/huangjingfeng/Desktop/專案/_reports/autolab-staging-env-bootstrap.json

npm run staging:check-env -- --env-file=.env.staging

必填值包含 DATABASE_URL、CLERK_SECRET_KEY、CLERK_PUBLISHABLE_KEY、VITE_CLERK_PUBLISHABLE_KEY、JWT_SECRET、ADMIN_USER_IDS、TURNSTILE_SECRET_KEY、VITE_TURNSTILE_SITE_KEY。

建議也補齊 RESEND_API_KEY、EMAIL_FROM、R2 相關 env 與 VITE_GOOGLE_MAPS_API_KEY。R2 影響後台圖片上傳，Google Maps key 影響地圖顯示。

密鑰收集清單：docs/autolab-staging-secrets-checklist.html。服務建立順序與設定檢查：docs/autolab-staging-services-setup.html。

Sensitive File Gate

在取得任何完整 DB dump、匯入資料包、Render env 或本地 .env.staging 後，先確認這些檔案不會被 git 追蹤。

npm run staging:check-sensitive-files -- \
  --html=/Users/huangjingfeng/Desktop/專案/_reports/autolab-sensitive-file-guard.html \
  --json=/Users/huangjingfeng/Desktop/專案/_reports/autolab-sensitive-file-guard.json

目前檢查會覆蓋 .env、.env.staging、_imports/、_reports/、database dump、副檔名壓縮 dump 與鏡像資產。若顯示 tracked risky files，先處理再繼續部署。

Database Gate

只對 staging database 執行 schema push。不要用 Manus/TiDB production DB，也不要用未確認的 production Neon DB。

set -a
source .env.staging
set +a
npm run staging:check-db-target -- --env-file=.env.staging

ALLOW_STAGING_SCHEMA_PUSH=true \
STAGING_DB_CONFIRM=autolab-staging \
npm run db:push:staging -- --env-file=.env.staging --apply

目前既有 Drizzle migration journal 仍是舊 MySQL 歷史，staging 目標則是 PostgreSQL/Neon。不要在未整理 migration history 前把舊 migration 直接套到 production；先用乾淨 staging DB 驗證 db:push 與資料匯入。

Data Package Gate

用查詢紀錄可整理出「可匯入」與「需要人工補資料」的資料包。這不是完整搬站資料，只能作為 staging 預填資料或匯入前審核。

npm run manus:prepare-data -- \
  --html=/Users/huangjingfeng/Desktop/專案/_reports/autolab-manus-data-package.html \
  --json=/Users/huangjingfeng/Desktop/專案/_reports/autolab-manus-data-package.json

  --data=/Users/huangjingfeng/Desktop/專案/_reports/autolab-manus-data-package.json

目前查詢紀錄可安全匯入的資料很少：分類 4 筆、標籤 7 筆、postTags 3 筆、文章 1 筆、活動 1 筆。多數文章、活動與報名資料缺少必填欄位，正式搬資料前仍需要完整資料庫 dump。

真正寫入 staging DB 時，必須明確加上保護旗標：

ALLOW_STAGING_DB_WRITE=true \

npm run manus:import-data -- \
  --data=/Users/huangjingfeng/Desktop/專案/_reports/autolab-manus-data-package.json \
  --tables=categories,tags \
  --apply

Preview Deploy Gate

  • 部署到 staging/preview URL，例如 Render preview，不綁定 autolab.cloud。
  • 確認公開頁：首頁、部落格、活動頁、/corporate-training、/ai-super-sales。
  • 確認後台頁：/admin/corporate-inquiries、/admin/ai-super-sales-registrations。
  • 用 staging email 測試表單通知，不使用正式金流。

Render preview URL 出來後，直接對該 URL 跑 smoke test：

npm run staging:smoke -- \
  --base-url=https://YOUR-RENDER-PREVIEW.onrender.com \
  --html=/Users/huangjingfeng/Desktop/專案/_reports/autolab-staging-smoke-preview.html \
  --json=/Users/huangjingfeng/Desktop/專案/_reports/autolab-staging-smoke-preview.json

staging:smoke 預設會拒絕直接測 https://www.autolab.cloud 或 https://autolab.cloud，避免把目前 Manus production 誤當 preview。

只有 preview smoke test、後台登入、兩個新後台頁與表單通知都通過後，才進 production cutover。

Production Cutover Gate

只有在 staging 驗證通過、資料匯入完整、表單通知與登入後台都確認後，才安排 DNS 切換。切換前保留 rollback 計畫與目前 Manus production 可用狀態。
