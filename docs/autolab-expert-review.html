Autolab Expert Review Notes

三位專家針對 deployment、資料搬遷、安全切換做的只讀審查彙整。此文件是 staging/preview 前的確認紀錄，不是正式切換指令。

共同結論：目前本機 staging 準備與 Git-backed deploy gate 已完成；還不建議進 Render preview deploy，更不能 production cutover。主要阻塞是外部 staging secrets 尚未完整、preview smoke/QA 尚未執行，以及 Manus full DB dump 尚未取得。

面向結論狀態
Deployment / RenderRender blueprint、staging gates、dashboard、production cutover gate 都已納入 Git-backed deploy。preview deploy 前仍必須填真實 staging env，不能使用 placeholder secrets。待 staging secrets
資料搬遷.manus/db 是 query logs，不是 full dump；現有 prepare/import 只適合少量 staging seed，不可作正式搬遷依據。待 full DB dump
安全與切換目前 staging 防線足夠保護 Manus production；production cutover gate 會輸出 NO_GO 直到 readiness、preflight、preview smoke 與 full dump 都通過。仍需補 DNS 原值、rollback owner、金流 QA 與 full preview QA。待人工確認

  • .env.staging 已建立且被 gitignore，權限為 600，目前只自動產生 JWT_SECRET。
  • staging:check-env 與 readiness 會拒絕 placeholder、production-looking DB、Manus/TiDB/MySQL DB、Clerk live key。
  • staging:check-db-target 已同步拒絕 manus token。
  • staging:smoke 預設拒絕 autolab.cloud / www.autolab.cloud，避免把 Manus production 當 preview。
  • staging:check-sensitive-files 已確認敏感路徑 12/12 會被 ignore，tracked risky files 為 0。
  • staging:check-render-env 已確認 .env.staging 與 render.yaml key 對齊，沒有缺 key 或 duplicate key。

已採納修正

  • validate-db-target.mjs 加入 manus forbidden token。
  • staging-preflight.mjs 的 Render env check 改用同一份 --env-file。
  • staging:check-git-deploy-files 已加入，用來確認 Render/staging 需要的 scripts/docs/source files 是否已納入 Git-backed deploy；最新為 63/63 tracked。
  • render.yaml build command 改為 npm ci --legacy-peer-deps，讓 preview build 更可重現。

  • 資料搬遷文件標註 current inspection 與舊 data package 數字差異，避免把 query-log 統計當成 full inventory。

下一步順序

  1. 建立獨立 Neon/PostgreSQL staging DB、Clerk staging app、Turnstile staging widget。
  2. 填入 .env.staging 或 Render env，重跑 staging:check-env -- --strict、staging:check-db-target、staging:check-git-deploy-files、staging:check-render-env、staging:check-sensitive-files。
  3. 確認 staging:check-git-deploy-files 維持全綠；不要 commit .env.staging、_imports/、_reports/ 或 DB dump。
  4. 只對 clean staging DB 執行 schema push，再用 staging sample seed 驗證後台畫面。
  5. 部署 Render preview，不綁正式網域；跑 preview smoke、人工 QA 與 production:cutover-gate。
  6. 取得 Manus full DB dump，只讀 inspect，補 full migration mapper 與 validation report。
  7. 只有 full data、preview QA、rollback 表格、DNS 原值、金流決策都完成後，才進 production cutover。
