Autolab Migration Unblock Plan

三位專家針對目前卡關點做的解法整理。目標是先讓 staging/preview 可安全前進，但不碰 Manus production、不改 DNS。

共同判斷：Git-backed deploy 檔案追蹤已解，現在主要卡住不是單一 bug，而是三條外部 gate 沒過：staging 外部 secrets 未建立、preview smoke/QA 尚未執行、Manus full DB dump 未取得。

卡關總表

卡關現況誰能解解除條件
Git-backed deploy 必要檔案已納入 Git-backed deploy；最新 staging:check-git-deploy-files 為 63/63 tracked。 Codex 已完成本機 commits；尚未 push/deploy 維持 allow-list 檢查全綠，不提交 .env.staging、_reports/、_imports/ 或 dump。
Staging secrets Readiness 為 21 pass、9 warn、7 fail；缺 DB、Clerk、Turnstile、ADMIN_USER_IDS。 需要使用者/外部後台建立；Codex 可核對與填入 建立 Neon/PostgreSQL staging DB、Clerk staging app、Turnstile widget，填入 env 後通過 strict check。
Full DB dump 目前只有 Manus query logs，333 檔、約 973 rows、缺 13/24 expected tables。 需要 Manus/原供應商提供；Codex 可做只讀檢查 取得 full SQL dump 或 per-table CSV/JSON 加 schema，再先跑 manus:inspect-dump。

最快解卡順序

  1. 先建 staging 外部服務：Neon DB、Clerk app、Turnstile widget 是 preview 前最低需求。
  2. 用 staging env 跑 strict gate：確認 7 個 required fail 歸零，再推 schema 到 clean staging DB。
  3. 部署 Render preview：不綁 www.autolab.cloud，先跑 smoke，再人工 QA 後台與表單。
  4. 同步要求 Manus full dump：資料搬遷和 preview 功能驗收可並行，但正式 cutover 前 full dump 必須完成。

Manus Full Dump 要求

  • 完整 production DB dump，SQL 或 dump 優先；不行就每張表 CSV/JSON。
  • 完整 schema/data dictionary：欄位型別、nullable、default、PK、unique、index、FK。
  • 媒體與附件：文章封面、活動圖、課程影片、下載檔、PDF、簡報、XLSX、uploads。
  • 原 URL 對照表、匯出時間、來源環境、增量 dump 機制。
