Autolab Production Cutover Checklist

這份清單只在 staging preview 完整通過後使用。目標是把正式網域切到自己的站，同時保留可回復到 Manus 的路徑。

目前不可執行正式切換：還缺真實 staging secrets、完整 Manus DB dump、preview 後台登入與表單驗證。這份文件是切換前準備，不是立即切換指令。

切換前備份

  • 匯出 staging DB：文章、活動、報名、聯絡、企業邀課、AI 超級業務報名、課程與付款相關資料。
  • 保存 DNS 當前記錄：A、CNAME、TXT、MX、CAA，尤其是目前指向 Manus 的記錄。
  • 保存 Render production service 設定與 env 清單，密鑰值只放在密鑰管理工具，不寫入 repo。
  • 確認 Manus production 仍可登入與回切。

DNS Cutover 步驟

  1. 把 TTL 先降到短時間，等待舊 TTL 生效。
  2. 確認 production service health check 通過：/api/health。
  3. 確認 production service 仍可用 preview URL 開啟首頁、/corporate-training、/ai-super-sales、後台登入。
  4. 切換正式網域 DNS 到 production service。
  5. 等待憑證與網域綁定完成。
  6. 對正式網域跑 smoke test。
npm run staging:smoke -- \
  --base-url=https://www.autolab.cloud \
  --allow-production-domain \
  --html=/Users/huangjingfeng/Desktop/專案/_reports/autolab-production-smoke.html \
  --json=/Users/huangjingfeng/Desktop/專案/_reports/autolab-production-smoke.json

這個 --allow-production-domain 只在 DNS 已切到新 production service 後使用。preview 或 staging 驗收時不要拿目前 Manus 正式網域當測試目標。

Rollback 條件

發生下列任一狀況，應優先回切 DNS 到 Manus 或切回上一個穩定 production service，再排查。

  • 首頁或主要公開頁 5xx 超過 5 分鐘。
  • 後台登入完全不可用且短時間無法修復。
  • 企業邀課或 AI 超級業務報名無法寫入資料庫。
  • 正式金流 callback 錯誤或付款記錄不一致。
  • DNS/SSL 問題導致大量使用者無法訪問。

Rollback 步驟

  1. 把 DNS 記錄改回切換前保存的 Manus production 設定。
  2. 確認正式網域回到 Manus 可開啟。
  3. 保留新 production service 與 logs，不要立即刪除，方便排查。
  4. 匯出切換期間新站收到的表單資料，避免遺失。
  5. 修復後重新走 preview QA，不直接再次切正式網域。
操作原則：正式切換只在 checklist 全部確認後執行；任何資料庫 schema 或資料匯入寫入都只對明確標記的 staging/production target 執行。
